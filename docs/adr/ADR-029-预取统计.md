# ADR-029：统计问答并存两条路径——服务端预取、确定性聚合、模型只表达

- 状态：Accepted
- 日期：2026-10-25
- 关联：[ADR-010](ADR-010-受控问数.md)（受控 Text-to-SQL）、[ADR-024](ADR-024-三级模型闸门.md)（模型门控）

## 背景

P3-a 收口后，统计问题只有一条路：问句 → `SqlPlan` → builder → guard → 只读 SQL。
数字是真的，但三件事做不到：

1. 明细 / 解释类追问（「哪三笔」「分别是什么」）只能拿到一个聚合数；
2. 每加一个维度都要改计划器与 builder，数据模型里没有的维度只能拒绝；
3. 即使模型参与表达，它拿到的仍是模板拼好的句子，不是「服务端已经查好、算好」的事实。

用户给出的原则是：**与其让模型写 SQL 再防它写错，不如让服务端把数据查好、算好，
模型只负责把事实说成人话。** 但直接替换会丢掉受控 SQL 已有的两条能力：可枚举维度的
库内聚合，以及超大数据量下的聚合下推。因此本轮的选择是**并存 + 确定性路由**。

## 决策

### 1. 路由是确定性代码，行数来自 scoped COUNT

`AnalyticsRouter.route(question, plan, row_count)` 只读三样东西：问句形状、`plan`、
一次已经按 `Identity` 过滤过的 `COUNT`。它不调用模型，不估计行数，同一输入必得同一
路由与同一理由码：

| 条件（按顺序） | 路由 | 理由码 |
|---|---|---|
| `plan is None` | `REFUSED` | 计划器的拒绝原因，缺省 `NO_PLAN` |
| 预取开关关闭 | `SQL` | `PREFETCH_DISABLED` |
| 问句要明细（`哪几笔` / `明细` / `展开`…） | `PREFETCH` | `DETAIL_REQUEST` |
| `group_by ∈ {status, month, day}` | `SQL` | `ENUMERABLE_DIMENSION` |
| `row_count > ANALYTICS_PREFETCH_MAX_ROWS` | `SQL` | `ROW_COUNT_OVER_THRESHOLD` |
| 其余 | `PREFETCH` | `SMALL_DATASET` |

`UNSUPPORTED_DIMENSION` 在最前面保持 P3-a 的拒绝语义：没有数据基础的维度仍然转人工，
不因为新增了预取路径就变成「猜一个维度」。

理由码与阈值写进 `analytics.route` span，路由可统计、可复现。

### 2. 事实在服务端算，模型看不到 L3

`PrefetchService` 的每条语句都带 `tenant_id` + `user_id`，问句只决定记录集、时间窗与
统计口径，**不决定看谁的数据**。小数据量在 Python 里对已过滤行求和；超过阈值时 L1 的
聚合留在 SQL；L3 明细最多保留最近 `ANALYTICS_PREFETCH_MAX_ROWS` 行供追问展开，
L2 固定只取最近 8 条进上下文，并明确标注「只展开最近 N 条明细，统计数字仍是全量」。

`AnalyticsSnapshot` 分三层：

| 层 | 内容 | 去向 |
|---|---|---|
| L1 | count / sum / group_by 聚合 | 进 prompt 与卡片 |
| L2 | 最近若干行的摘要 | 进 prompt，与 L1 共享 1,400 字符硬预算 |
| L3 | 完整明细行 | **永不进 prompt**；只存在进程内 `SnapshotStore`，按 `query_id` 展开 |

预算裁剪是确定性的：先丢最旧的 L2 行并留下说明，同一份数据两次运行得到同一段上下文。

### 3. 表达失败只降级措辞，不改事实

预取路径只在 `AGENT_MODE=pydantic_ai` 且 `ANALYTICS_NARRATION_ENABLED=true` 时调用
一次模型；`rules` 模式、开关关闭、受控 SQL 模板路径都是零调用。Prompt 固定带一句约束
（不得计算、不得补充数字、不得提及数据库结构），但**不依赖模型遵守提示词**：

- `FactualityGuard` 独立提取回复里的阿拉伯数字与量词前的中文数字；字母后粘连的数字
  （`DE20010003`）也要读出来，否则改一位单据号会漏检；
- 数字带正负号，四种写法 `-129.00` / `−129.00` / `－129.00` / `负129.00` 都先归一为
  负号再比对，均不等于 `129.00`；
- 日期整段抽取，ISO、`YYYY年M月D日`、`M月D日` / `M月D号` 都归一化后比较：
  `2026-09-20` 与 `2026-09-21` 不是同一事实；时间戳只登记整天与 `MM-DD`，
  **不登记年/月/日裸分量**，否则「20 笔」会借最近一行的 20 日通过。
  `MM-DD` 是归一化**比对键**，不是让模型引用的形态：事实侧的整天加这个键，
  回复侧的省略年份日期归一成同一个键；
- 百分号保留在比对键里：事实集合只有计数与金额，没有比率，`50%` 不等于计数 `50`；
  `%` / `％` / `﹪` / `٪` 四种写法、数字与符号之间的空白（`50 %`）、以及
  `百分之五十` 整段都按同一个比率声明处理；
- 「最近一笔」「第一笔」「下一笔」里的「一 / 两」是定语不是计数：紧跟在
  `最近 / 第 / 下 / 这 / 那 / 前 / 另 / 同 / 每` 之后的「一 / 两」不参与核对；
  「只有一笔」「共有五笔」「前五笔」仍按计数校验。例外只认紧邻写法，前缀与数字
  之间带空格时按普通数字核对（安全方向）；「前两笔」「另两笔」也按定语放行、
  不核对其中的 2，属已声明边界；
- 每个数字必须能在事实集合里找到（含金额的元/分两种写法与已知日期）；
- 找不到就丢弃模型句子，回退确定性模板；
- trace 写 `analytics.faithfulness`，失败时记 `status=FAILED` 与未命中的数字，
  **不写整段回复**；
- 卡片字段与数字不变，只有措辞来源变化。

Guard 是**扁平集合的成员校验**，不做字段级绑定：`count=3` 时「共有 129 笔」里
的 129 来自金额，同样会通过；金额的分写法与元写法互为事实，所以把分整数当元、
用千分位写出的金额（`129.00` → `12,900.00`）也不会被拦。它也只核对数字、整天日期
与比率形态，不逐词核对「已到账」这类状态措辞。这些边界都是已声明边界，不是
「全部事实都已机器验证」；收窄到字段级比对不在本轮范围。

### 4. 追问按 `query_id` 展开，不重新查库

会话槽位保存 `last_analytics_query_id`。同一会话里「哪几笔 / 明细」命中上一轮快照、
且本轮仍被判为统计型（`SELF_ANALYTICS` 或 `UNKNOWN`）时：

- 返回 `kind=analytics_detail` 的卡片，`card_id` 仍是同一个 `query_id`；
- 不调用模型，也不重新执行 SQL；
- 政策 / 退款 / 工单等意图即使带「明细」也不展开，按原意图回答；
- 快照不存在、已过期或不属于当前身份时，要求重新提出统计问题，不返回旧数据；
- 客户再问一个新统计时，槽位被新 `query_id` 替换；走 SQL 的统计轮次没有快照，
  因此清空槽位，避免把上一次预取结果当成本次。

`SnapshotStore` 的键是 `query_id`，值是 `(tenant_id, user_id)` 绑定 + TTL（默认 900 秒）；
写入新快照时会顺带清掉已经过期的旧快照。

### 5. 配置与回退

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `ANALYTICS_PREFETCH_ENABLED` | `true` | 关闭后逐位回到 P3-a 的受控 SQL |
| `ANALYTICS_PREFETCH_MAX_ROWS` | `200` | 路由阈值与 L3 明细保留上限（L2 固定 8 条） |
| `ANALYTICS_SNAPSHOT_TTL_SECONDS` | `900` | L3 快照存活时间 |
| `ANALYTICS_NARRATION_ENABLED` | `true` | 是否允许预取路径调用模型表达 |

`analytics` 响应与卡片的新增字段只有 `route`；既有字段名与形状不变，P3-a 的 4 条
维度用例与 3 条评测继续通过。

## 后果

- **收益**：明细类问题能答、能展开；统计数字只有一个来源；模型改数、编造新数、
  挪动日期会被 guard 拦住（复用已有数字冒充另一字段不在拦截范围，见上）；
  路由与回退都可测。
- **成本**：预取路径多一次表达调用（约 1,400 字符事实 + 问句的输入 token）；真实模型
  延迟取决于端点，本机没有把该项测成数字，报告里必须写明「未测」而不是给一个估计值。
- **边界**：快照只在当前进程内。多 worker 下追问可能落到没有快照的进程，此时按
  「过期 / 不存在」要求重新提问；跨进程共享留到生产化批次（P7）。
- **边界**：阈值 200 是当前演示数据上的标定值，换数据量要重跑路由分布；它不是质量门槛。
- **边界**：Guard 只核对数字、整天日期与比率形态，不逐词核对状态类定性措辞；
  扁平集合不拦跨字段复用，金额的分/元两种写法互为事实，`129.00` 与 `12,900.00`
  都算已知；模板回退是兜底，不等于所有语义都被机器验证。
- **不做**：不放开自由 SQL，不让模型生成 SQL 或聚合代码，不把 L3 放进 prompt，
  不改支持集 / Golden / 回放的判定口径。

## 证据

- `tests/test_analytics_router.py`（11）：六个分支、理由码、同输入同结果、开关回退。
- `tests/test_analytics_prefetch.py`（18）：身份隔离、时间窗、count / sum / group_by
  与受控 SQL 逐位一致、超阈值截断与标注、超阈值分组走 SQL 时与 Python 逐位一致、
  写入新快照清理过期项。
- `tests/test_analytics_narrative.py`（15）：预算、L3 不出现、固定约束、rules 零调用、
  失败回退、两条路径同一模板。
- `tests/test_analytics_faithfulness.py`（49）：正确数字通过；改数、编造、夸大、四种负号
  写法（`-` / `−` / `－` / `负`）与挪动一天的日期（ISO、`YYYY年M月D日`、`M月D日` /
  `M月D号`）被拦截；粘连在字母后的单据号数字（`DE20010003` → `DE20019999`）被拦截；
  日期分量（年/月/日）不得冒充笔数；编造的百分比（`50%` / `50 %` / `50％` / `50﹪` /
  `50٪` / `百分之五十` 六种写法 vs 计数 `50`）被拦截，真实计数仍通过；
  「最近一笔」不拦而「只有一笔」「前五笔」按计数拦；日期与千分位不误伤；失败句子被丢弃。
- `tests/test_analytics_followup.py`（9）：同 `query_id` 展开、零模型调用、过期与跨身份
  拒绝、新统计替换旧快照、政策问句不展开、SQL 统计轮次清空槽位。
- 回放口径：`analytics.route` / `analytics.prefetch` / `analytics.expand` 是决策与预算
  记录，没有写库或外部调用，因此计入 `evals/replay.py` 的只读工具；否则可回放会话会从
  46 段掉到 42 段（`tests/test_analytics_prefetch.py` 有一条单测钉住该分类）。
- P3-a 回归：`tests/test_sql_dimensions.py` 4 条、`evals/analytics_dimension_set.json` 3/3。
