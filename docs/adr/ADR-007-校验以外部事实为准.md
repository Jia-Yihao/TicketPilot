# ADR-007：以权威记录验证结果，五种验证状态

- 状态：Accepted
- 日期：2026-10-23

## 背景

“工具调用返回成功”不等于“业务动作成功”。退款请求被受理后可能失败、延迟或被撤销。向用户宣称成功必须有独立证据。

## 决策

`VerificationService.verify_refund` 独立检查：

1. 退款记录存在
2. 记录属于目标订单
3. 金额与审批金额一致
4. 状态为 `SUCCEEDED`
5. 应用后的可退余额不为负

映射为五种状态：

| 状态 | 含义 |
|---|---|
| `VERIFIED_SUCCESS` | 权威记录确认成功且不变量成立 |
| `PARTIAL_SUCCESS` | 部分条件成立，需进一步处理 |
| `PENDING_CONFIRMATION` | 结果未确认，继续对账 |
| `FAILED` | 明确失败 |
| `NEEDS_HUMAN_REVIEW` | 数据异常或不变量被破坏 |

任务状态与验证状态分离：任务 `SUCCEEDED` 只表示流程完成，`result.outcome` 才代表业务结论。

## 后果

- 不会把“请求已受理”说成“退款成功”
- 余额只应用一次，异常可转人工
- 验证逻辑与执行逻辑解耦，可单测
- 当前 Verifier 主要覆盖退款；订单/物流使用轻量 checks，尚未抽象成通用规则引擎

## 备选方案

- 信任工具返回：拒绝，无法发现外部失败
- 只落日志人工核对：拒绝，不可规模化
