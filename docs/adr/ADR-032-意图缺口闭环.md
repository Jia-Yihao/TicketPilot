# ADR-032：意图缺口闭环——去重、人工确认与同一份语料

- 状态：已接受
- 日期：2026-10-26
- 关联：ADR-028（意图语料评测）、P5

## 背景

ADR-028 把意图质量从「按词表写的 61 条」换成了两层 held-out 语料，但它只解决了
「怎么量」。漏掉的句子仍然由人从 `scripts/sample_traces.py` 的 JSONL 里挑：同一句
漏判会在多个周期重复出现，没人能回答「这一轮补了什么、覆盖率涨了多少」，也没有
任何机制阻止一个模型建议被直接当成金标。

## 决策

### 1. 一个按规范化文本去重的队列

`evals/intent_gaps.py` 定义队列：

- `normalize()`：NFKC → casefold → 去掉 Unicode 标点 → 空白折叠为单个空格。
  只折叠不删除空格，避免把 `a b` 与 `ab` 误合并。该函数定义在
  `scripts/build_intent_set.py`，队列与跨层去重共用同一份实现。
- `dedup_key()`：规范化文本的 SHA-256；记录 id 是 `gap-` + 前 12 位。
- 租户只以 `sha256("tenant:" + id)` 保存；入队时只保留
  `dataset` / `file` / `line` / `selection_id` 四个来源键。
- 同一 key 再次被抽到只增加 `observations`、刷新 `last_cycle`、合并租户哈希与信号；
  **不改状态**。`CLOSED` / `IGNORED` 不会因为再次出现而回到 `OPEN`。

### 2. 模型只能提议，人工才能关闭

- `propose()` 只向 `proposals` 追加 `{source: model, label, note, by, cycle}`，
  `status` 与 `label` 不动，也不产生闭包行。
- `close()` / `ignore()` 要求显式 `confirm_human=True`、非空 `by` 与非空 `note`；
  关闭还要求标签属于现有的 12 个意图。失败只抛错，不落盘。
- `IGNORED` 表示「这句话本来就该转人工」，不是缺口；它永远不进语料。

### 3. 关闭的缺口进同一份语料

- `closure_rows()` 把 `CLOSED` 记录导出为 `evals/intent/gap_closures.jsonl`：
  `layer=authored_gap`、`label_source=human`、
  `provenance={"gap_id", "source": "intent-gap-loop", "cycle"}`。
- `scripts/build_intent_set.py` 把它合并进 `authored_gap`，并在合并后做**跨层**文本
  去重；去重键与队列相同（`normalize()` 后的文本），只差一个全角标点也会失败。
  重复文本直接失败，不另造分母，也不把同一句同时算进措辞证据与覆盖证据。
- 数据集的 `sources` 记录闭包文件与 SHA-256；`--check` 仍逐字复算。

### 4. 周期报告只做分层对比

`build_report()` 固定输出：队列的 `OPEN` / `CLOSED` / `IGNORED`、`new_cases`、
本轮关闭 / 忽略数、仍开放列表，以及 `external` 与 `authored_gap` 各自的
`cases` / `coverage` / `false_unknown` 前后值与 delta。报告不产生两层相加的单一准确率；
`after.invariants.ok=false` 时置 `gate_regression=true` 并列出失败项。队列与报告都由
固定序列化器输出，同一输入逐字一致。

报告的 before 侧不依赖 `.tmp`：关闭前的完整指标快照提交为
`evals/intent/gap_metrics_before.json`。重算方式是临时清空 `gap_closures.jsonl`、
`build_intent_set.py --force`（345 条）、`intent_metrics.py --json` 写出快照，再恢复
闭包并重建 346 条；`tests/test_intent_gaps.py` 钉住快照与 `gap_report.json` 的 before
侧一致。`close` 先写队列（事实源）、再写由队列导出的闭包，闭包写抛错时回滚队列，
写完还读回校验两文件；短写会被读回校验发现并退出 2（不自动回滚，留给下一次显式修复），
把半份状态限制在「可检测、需显式修复」的范围。

## 后果

正面：

- 一条漏判只入队一次，跨租户合并，原始租户 ID 不落盘。
- 「模型建议」与「人工金标」在数据结构上分开；没有 `--confirm-human` 就写不进语料。
- 每轮都能回答「新增几条、覆盖与 `false_unknown` 怎么变、旧门槛是否退化」。
- 关闭的缺口与手写补位共用 `authored_gap` 分母，历史读数仍可比。

代价与边界：

- 关闭一条缺口不等于修好分类器。2026-10-26 关闭的
  `我刚拍的刀纸地址选错了` 仍被规则判成 `UNKNOWN`，报告如实显示
  `authored_gap` coverage 0.5000 → 0.4966、`false_unknown` 60 → 61。这是
  「让缺口可见」的证据，不是「覆盖率提升」的假象。
- 队列只收规则判成 `UNKNOWN` 的句子；规则读错但读成另一个已知意图的句子仍要靠
  评测集发现，不在本闭环内。
- 没有语义聚类：只有规范化文本去重，近义说法仍可能是两条记录。
- 不自动改 `intents.yaml` 或 `routing.py` 的 cue 表；词表改动仍需人工 review。
- 单人标注，没有第二标注者与一致性系数；本轮新增一条闭包用例，规模很小。

## 被否决的方案

- **模型标签直接进 gold**：无法复核，且会把模型的系统性偏差写成语料事实。
- **另建一套「缺口集」分母**：会制造第二份质量结论，抵消 ADR-028 的分层口径。
- **关闭时自动改 cue 表**：把评测、词表与路由混成一次不可复核的写操作。
- **原始租户 ID 入库**：队列会进版本库，租户标识不应出现在可提交的文件里。
- **按语义簇去重**：需要模型或 embedding，破坏离线、确定性；本轮只做文本规范化。

## 证据

- `tests/test_intent_gaps.py` 31 条：规范化 / 去重、跨租户合并且不写原始 ID、终态不
  重开、模型提议不改状态、人工确认（close / ignore）各三条失败路径、未知标签拒绝、
  闭包行来源、忽略不入语料、分层报告与门槛退化、稳定渲染与重载、报告不受入队顺序影响、
  构建器合并与跨层重复（含仅标点不同）拒绝、before 快照与报告一致、CLI 无确认不写盘、
  写队列 / 写闭包失败时不留半份状态、缺队列时明确报错与完整往返。
- `tests/test_intent_eval.py` 25 条继续通过，来源断言接受 `gap_id` 闭包。
- `python scripts/build_intent_set.py --check` → `INTENT SET OK cases=346`。
- 2026-10-26 初始队列：3 条（2 `OPEN` + 1 `CLOSED`）；关闭 `ORDER_QUERY` 一条后
  语料 345 → 346（`authored_gap` 144 → 145），`gap_report.json` 记录 before/after。
