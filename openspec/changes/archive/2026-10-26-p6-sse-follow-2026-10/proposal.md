# P6：任务事件实时推送（轮询订阅 + 断点续传）

## 为什么改

`GET /api/v1/tasks/{task_id}/events` 先把已持久化事件取成列表再逐条吐出，
发完即关闭。演示说的是「实时时间线」，实际只能刷新 / 重放。FastAPI 的
`StreamingResponse` 已在位，缺的是「事件写入后可被唤醒」。

## 改什么

1. 新增 `TaskRuntime.follow_events()`：先回放 `Last-Event-ID` 之后的事件，
   再按固定间隔轮询同一张 `task_events` 表；任务终态且无新事件后结束。
2. 走数据库轮询而不是进程内回调：多个 worker 共享同一张表，单进程 / 多进程
   行为一致，不需要新中间件。
3. 心跳：空闲时按固定间隔发送 SSE 注释帧，避免代理层掐断。
4. `Last-Event-ID` 继续生效；已消费的事件不再重复，断点之后的不丢。
5. 事件帧形状、权限与既有回放完全一致；加 `follow=false` 可回到旧行为。

## 不做

- 不引入 Redis / 消息总线；这是演示增强，不是生产消息系统。
- 不改变事件写入事务与顺序。
