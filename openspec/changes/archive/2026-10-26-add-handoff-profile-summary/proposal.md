# F-8 移交包携带客户档案摘要

## 为什么

客户档案里的 `history_summary` 是客户**自己**写下的自由文本。它被脱敏、被存下来、能被导出，
但今天**没有任何消费方**——除了「客户自己看」（`GET /api/v1/memory`）。坐席接手一通会话时，
移交包里只有**本会话**的逐轮要点（`transcript_digest`）、意图轨迹、槽位与政策引用，
没有一句「这个客户之前说过什么」。客户在上一通会话里已经讲过一遍的事，接手的人还得再问一遍。

这就是 NEXT_STEPS 的 F-8「长期记忆没有出口（低，顺手）」：数据在，出口没有。

这一轮只接**一个**出口：把**已脱敏的**档案摘要带进移交包，并标明来源与长度上限，
让坐席有判断依据。它不扩大模型的输入面、不改客户可见的话术、不改档案的写入路径。

## 改什么

1. 移交包新增三个键：`history_summary`（脱敏并截断后的正文）、`history_summary_source`
   （来源标注，恒为 `customer_profiles.history_summary`）、`history_summary_max_chars`
   （实际生效的截断上限）。**只在有摘要时出现**；没有摘要时三个键都不占位。
2. 内容整形发生在**移交包落库前**：先脱敏、后截断，截断用与本会话要点摘要**同一个上限、
   同一个函数**。装配移交包的既有入口保持纯函数（不接会话、不查库），既有产出键逐字不变。
3. 读取侧新增一个只读出口：按租户与用户逐值相等取档案摘要**一列**，不建行、不改更新时间、
   **不写审计**。读的是**对话客户本人**的档案，不是坐席的档案。
4. 控制台的案件详情区**条件渲染**：三个键存在才显示，缺失不渲染、不显示占位符；
   前端不自带任何「这个客户之前说过什么」的事实副本。

## 不改什么

- 不进客户回复、不进提示词、不进任务上下文、不进追踪属性。档案摘要**只**出现在移交包
  （案件详情）里，队列行摘要仍只带本会话要点。
- 不改档案的写入路径、字段集与 500 字上限；不动客户「自己看档案」的那条出口。
- 不改答案路径的覆盖层：回复侧的四种既有效果与断言逐字不变。
- 不做内容白名单、关键词过滤、敏感词拦截；不引入跨会话检索、时间线与版本历史。
- 不新增迁移、不新增配置项、不新增依赖。
